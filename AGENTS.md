# Repository Instructions

## GitHub Issues and Pull Requests

- Write issue and pull request titles and bodies in Korean. Preserve code,
  identifiers, and commands in their original form.
- Before authoring an issue or pull request, inspect the repository's available
  labels, issue types, and issue fields. Set the applicable metadata appropriately.
- Reference related issues in the body. When a pull request resolves an issue,
  link it with an appropriate GitHub closing keyword, such as `Closes #123`.
- Link working branches to their related issues through GitHub's Development
  feature when available. Do not link unrelated issues or branches.
- If a feature is unsupported or permissions prevent setting metadata or links,
  report the unset item and the reason instead of substituting another mechanism.
- Follow the existing GitHub and development branch workflow alongside these
  conventions.
